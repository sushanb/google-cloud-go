Bigtable Session Debug UI

sessionz · channelz · configz

A channelz-style, zero-JS debug UI for the Bigtable Go data client's session-based transport. Live state of every session pool, gRPC channel, and server-driven configuration — all from atomic counters already on the hot path. No new goroutines, no performance hit.

Mount: http.Handle("/debug/sessionz/", http.StripPrefix("/debug/sessionz", sessionz.Handler(client)))
Branch: feat/bigtable-sessionz-debug

sessionz

Per-pool / per-session state — drill into any pool to see who's serving what

What it shows

  • pool sizes, picker, scale history
  • per session state, PeerInfo (AFE region/subzone, GFE id, transport type)
  • RPCs OK / errors / retries, msgs sent/recv (click for type breakdown)
  • latency p50 / p95 / p99 from server-reported BackendLatency
  • cluster routing tally per ClusterId
  • lifecycle opened / closed / close reasons / config-listener fires
  • slow vRPCs last 100 calls over threshold
  • sparklines ok/s, err/s, session count, last 5 min
  • churn histogram session lifetimes bucketed <10s … ≥24h
  • OpenSessionRequest proto rendered as JSON

channelz

Per-pool gRPC channel inventory — classic data path + dedicated session path

What it shows

  • pool LB policy, instance, app profile, channel count
  • per channel gRPC state, ALTS / IP, draining flag
  • load outstanding unary / streaming, picks, errors, age
  • last activity distinguishes idle vs working
  • sessions on me reverse lookup of every session riding this channel — clicks back into sessionz

Bidirectional with sessionz

  • sessionz Ch # → channelz#channel-session-2
  • channelz Sessions col → sessionz pool detail

configz + Diverter + Lifecycle

Server-driven config & the new SessionState machine

configz — the server's voice

  • Latest GetClientConfiguration response rendered as protojson
  • Instance, app profile, config-seq, fetched-ago, validity window
  • Last 100 polls (time, duration, OK/error code)
  • "Polls stopped 4 minutes ago" jumps out at a glance

Diverter

  • Target SessionLoad 0.0 – 1.0 from the control plane
  • Running pick totals: session_picks / classic_picks
  • Actual ratio computed from totals — catches drift from target

SessionState lifecycle (matches Java)

New → Starting → Active ↓ Closing ── drain admitted vRPCs ↓ WaitServerClose ── CloseSession sent ↓ Closed
  • GoAway transitions to Closing, drains, sends CloseSession, parks in WaitServerClose
  • Pool monitor force-closes sessions stuck in WaitServerClose > 30s — bounds the case where the server forgets to EOF
  • Close reasons surface in sessionz: User Downsize GoAway MissedHeartbeat Error
