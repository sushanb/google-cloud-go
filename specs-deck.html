Session Client is robust / thick

Journey: One Shot Prompting

Session Client is an API change plus a family of new components that must land without any regression or user-visible change.

One-shot Prompting FAILED

  1. Session Client is >>> an API change — ~30k lines of code, >10 components/layers.
  2. No shared axis. Every iteration devolves into “does this look right?”

Fix

  1. For each subcomponent, write the major non-negotiable spec. The rules that MUST hold.
  2. Write an overall component spec, defining ownership and flow — so we never couple things together.
  3. Set up a review system that ensures the code it touches follows the spec. PostToolUse hook on session-file edits fires two reviewer subagents automatically — no manual invocation, no forgotten step.
  4. Reviewer subagents read the spec, walk the diff, and report PASS / VIOLATION / AMBIGUOUS per invariant.
  5. Specs are a living doc — specs mutate with human in the loop.

What a SPEC actually looks like

One invariant from SESSION_SPEC.md — the GOAWAY-handling rule (#6). Every invariant is written as a numbered order-of-operations the reviewer can walk step by step.

#6 — GOAWAY does NOT cancel the in-flight vRPC

  1. If the server sends a GOAWAY before the session has even finished starting up, treat it as a protocol oddity, record it, and ignore the frame.
  2. Move the session from ready to closing — but only if it isn’t already in a terminal state, so a late GOAWAY on a finished session is a no-op.
  3. Tell the pool immediately that this session is going away, so it stops routing new work to it well before the underlying stream actually closes.
  4. Lock in “GoAway” as the close reason; later, more generic close classifications must not overwrite it.
  5. Do not cancel the in-flight request — if the server delivers the response before dropping the stream, the request still completes successfully.
  6. Kick off the graceful shutdown from a background task under a bounded deadline, so the caller’s path is never blocked by the close.

What makes this a useful spec

  • Java parity note names the file. When Go and Java differ, the reviewer surfaces it and the human decides.
  • Deprecation lives in the spec.
  • Subagent pipeline scales beyond “does this look right?”

Part C — Ownership matrix (sole owner per concern)

Every mutable concern names exactly one owner. Others read via accessor/interface; no parallel copies.

Traffic split ratio (session vs classic) — owned by Diverter.sessionLoadBits (atomic float64); driven by ClientConfigurationManager.SessionLoadListener.

Per-attempt ClusterInfo (session path) — owned by InvokeResult.ClusterInfo; stamped by sessionTable.stampAttempt; MUST NOT be re-derived from headers.

Session-tracer OTel histograms — owned by sessionTracer; registered once by InitializeSessionMetrics; sole writer for transport_latencies under the positive-delta gate at session_pool.go:650.

Why three parts, not one. Part A drifts and everyone knows it. Part B is the durable prescriptive layer — violations block PRs. Part C names sole owners so a future if/else can’t innocently add a second writer that silently drifts labels or state.

Prompt (Simple) — typed accessors for an atomic field

Simplest shape: pure passthrough refactor. No behavior change, one file, one reviewer pass.

Prompt

Small-task promptAdd a getter and CAS wrapper for Session.activeRPC (atomic.Pointer[vrpcImpl]) so call sites don’t reach the atomic directly. Route all 11 production .Load() and .CompareAndSwap() sites through the wrappers; leave test .Store() sites direct (fixture setup only).

Flow

  1. Edit. Add (*Session).LoadActiveVRPC() + (*Session).CASActiveVRPC(old, new). Rewire 11 call sites via gopls rename.
  2. Hook fires. PostToolUse on any session_*.go edit auto-invokes both reviewer subagents in parallel.
  3. session-reviewer confirms SESSION_SPEC.md #2 (one-in-flight vRPC via CAS) is preserved bit-for-bit — wrappers are identity; the CAS still fails only for caller (pool) bugs, never backpressure.
  4. session-component-review confirms no boundary crossings and Part C row for “In-flight vRPC slot” still names Session.activeRPC as sole owner. No ownership change.
  5. Smoke gate. go test -race -count=1 -short -timeout=90s ./internal/transport/ green.
  6. Commit. Both reports PASS; ship it.
Why this fits the small bucket. One concept, one file, one invariant to preserve. The prompt names the target interface, both call-site classes (production vs test), and the exact rewire — leaving nothing for the model to invent.

Prompt (Large) — tcpz: per-conn TCP_INFO as a debug page

Introduces something none of the other 6 z-pages did: a fourth kind of state (TCP-level, not pool/session/channel/config), a Linux-only syscall on the read path, and a new first-class Handler arg.

Prompt

Large-task promptAdd a tcpz debug page that exposes TCP_INFO stats for every connection tracked in the client’s channel pool. Wire a custom dialer at Client construction to capture each net.Conn into a bigtable.TCPStats collector; the view calls getsockopt(SOL_TCP, TCP_INFO) per socket on render. Must be nil-safe: debugview.Handler(client, nil) renders “collector not attached” on /tcpz/. Six incremental commits: page skeleton, retrans diagnostics, PMTU column, flow control, per-peer grouping, auto-refresh throttle.

Flow — why the specs made this survivable

  • SESSION_COMPONENT_SPEC.md B3 — debugview accesses pool/session state ONLY via the three provider interfaces (SessionDebugProvider / ChannelDebugProvider / ConfigDebugProvider). TCP_INFO isn’t any of those — forced the decision to introduce *bigtable.TCPStats as a fourth first-class Handler arg rather than smuggling it through an existing provider. Part C gained a new ownership row in the same PR.
  • SESSION_POOL_SPEC.md #4 — z-pages MUST NOT block hot-path latencies. getsockopt is a syscall; the collector holds live net.Conn refs. Reviewer enforced: snapshot-copy the conn list under RLock, release, then iterate + syscall outside the lock. Otherwise a hung syscall would freeze every subsequent connection registration.
  • SESSION_COMPONENT_SPEC.md B10 — z-pages render, they don’t compute. The “flag sub-1500 PMTU paths” column added in commit 3 lives on the DTO producer (tcp_info_linux.go), not in the template — so the JSON consumer sees the same flag as the HTML view.
  • Nil-safety contract enforced across all 7 z-pages. debugview.Handler(client, nil) must not panic. That contract is why tcpz slotted in without adding a second constructor.

Six commits, six clean reviews

Why 6 commits, not one. The initial page shipped as one prompt (e8c80cff91 tcpz — per-conn TCP_INFO debug endpoint); every subsequent field — retrans diagnostics, PMTU, flow control, per-peer grouping, auto-refresh throttle — was its own small one-shot prompt because the base was solid. Specs made incremental additions safe: reviewer confirmed each new field followed B10 (compute on producer), and each render pass followed POOL #4 (no lock across syscall). Six commits, six clean reviews, no regressions.

Big features break down under specs. The specs didn’t just gate the initial commit — they made the next five commits landable as small tasks.

Workflow

  1. PLAN. For anything above a simple prompt, enter plan mode. The model explores the codebase, drafts a written plan (saved to ~/.claude/plans/*.md), and asks for approval before writing code.
  2. FLUSH. Human read of the plan — usually the point where scope shrinks. “Do the 2-site POC, not the full migration” came from flushing, not from the model.
  3. EXECUTE. Only after the plan is signed off. Reviewer hooks + specs enforce that the executed diff matches the approved shape.

Limitations

Failure modeWhat it looks like
1. Race conditions. Concurrency bugs that require holding 3+ atomics/locks in your head — the model finds the local fix but misses the cross-resource invariant. R1’s three variants and R2’s two legs (state, activeRPC, sendMu, sessionList) were all in this bucket.
2. if/else fixes instead of scoped ones. The model reaches for the smallest local branch — usually right at the symptom site — rather than following the ownership matrix. Diverter grows an if isSessionPath; z-page grows an if collector != nil inline instead of at the constructor.
